### Snags

1. **The root README sends a clean-clone user to the wrong product.** The top-level README's only "Run it" section is the pre-existing Star Wars gift finder. Step 1 needs the Doppler CLI and the `jedi-pack` project. Ran `./run.sh` and got `env: 'doppler': No such file or directory` (exit 127). Got past it by following the root README's "Read: inbox/README.md (the submission)" link. That link is in the README, but a judge who scrolls to "Run it" hits this first.
2. **The Quick start code block doesn't say which folder to run it in until after the block.** Ran `cp .env.example .env` at the root and got `cp: cannot stat '.env.example': No such file or directory`. The line under the block ("Run these from the `inbox/` folder") fixes it. Got past it with `cd inbox`.
3. **Node version.** The README says "Needs Node 22 or newer"; the box has v20.19.2. `npm ci` warns `EBADENGINE ... required: { node: '>=22' }`. I didn't install Node 22, because the README gives no install method. Everything in sample mode ran fine on Node 20, so the requirement looks stricter than needed, or Node 22 is only needed for paths I didn't exercise (the README says the bundle exists "because Node 22 cannot load the reference's TypeScript at run time").
4. **Port mismatch in the API section.** The README says the default port is 8000, but its curl block hard-codes `B=http://127.0.0.1:8810` (the dev VM). Ran `curl -s http://127.0.0.1:8810/health` and got curl exit 7 (connection refused). Guessed `B=http://127.0.0.1:8000` from the Quick start's port line.
5. **A reused run_id returns a Conflict.** Re-posting `input_examples/example_1.json` gives `"type":"Conflict","message":"run_id example-1 was already used"`. Not documented, so a judge re-running the examples would be surprised. Got past it by restarting the server or using a new run_id. Not a README instruction, just noted.
6. **`npm test` fails 8 tests on a clean clone that followed the Quick start.** Because the Quick start creates `inbox/.env` (with placeholders), `tests/usl.test.mjs` and `tests/usl_drift.test.mjs` think they're live (`HAS_ENV = existsSync(.env)`) and try Zetaris. Errors: `zetaris: a query name is required to answer from the cached rows` and `ENOENT: no such file or directory, open '.../inbox/data/sample/usl_drift_raw.json'`, 8 times (tests 370 to 377). The README says only "Run `npm test` for the current count". To diagnose, I temporarily moved `.env` aside (my own step, not in the README) and got **391 tests, 380 pass, 0 fail, 11 skipped**, which matches the latest commit message. Suggested fix: key the live tests on a real credential (for example a non-placeholder `ZETARIS_REST_URL` or `LIVE_TESTS=1`), not on `.env` existing. The same `.env` (with `SAMPLE_MODE=false`) is why the plain `npm run cli -- run --thread T02` spends 20 s on refused live calls.
7. **`npm run doctor` exits 0 when all three providers fail.** Minor, but a CI or a judge's script can't tell from the exit code.
